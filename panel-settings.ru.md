# Гайд по настройкам панели

Этот документ описывает вкладки Settings и их влияние на поведение панели.

Для общей карты документации см. [panel-overview.ru.md](./panel-overview.ru.md).

## Как устроен раздел Settings

Settings разбит на пять вкладок:

- System - производительность, кэш, лимиты и SSH-pool.
- Subscription - внешний вид и поведение клиентских подписок.
- Security - администратор, 2FA, API keys, MCP и webhooks.
- Backup - локальные и S3 backups, расписание и восстановление.
- Maintenance - обслуживающие и потенциально опасные операции.

Часть форм на странице Settings независимы друг от друга. Это удобно для точечных изменений, но требует внимательности: перед сохранением нужно понимать, какой именно блок вы меняете.

## System

Вкладка System управляет глобальным поведением панели и рабочих сервисов.

### Что обычно находится здесь

- load balancing;
- поведение кэша;
- rate limits для подписок;
- настройки SSH pool;
- параметры node auth.

### Когда менять System-настройки

- если выросло число пользователей и нужен другой баланс производительности и свежести кэша;
- если SSH-операции работают медленно или нестабильно;
- если меняется стратегия распределения пользователей по узлам;
- если нужно ослабить или ужесточить требования к node auth.

### Что важно проверять после изменений

- создаются ли подписки без задержек;
- стабильно ли работают sync и SSH-операции;
- не выросло ли число ошибок на узлах;
- не пропали ли ожидаемые узлы у пользователей.

## Subscription

Вкладка Subscription отвечает за то, как выглядит и ведёт себя подписка для клиентских приложений.

### Что можно настраивать

- support URL и web page URL;
- логотип и title страницы подписки;
- интервал обновления;
- набор кнопок и ссылок в клиентском представлении;
- HAPP-специфичные параметры;
- режимы, связанные с HWID и объявлением ограничений устройствам.

### Практический смысл

Эта вкладка не только меняет внешний вид. Она определяет, что увидит конечный клиент и как его приложение будет интерпретировать подписку.

### На что обратить внимание

- слишком частый update interval может увеличить нагрузку;
- ошибки в пользовательских кнопках приводят к битым ссылкам в клиенте;
- HAPP-специфичные опции надо тестировать на реальном клиенте, а не только по JSON.

## Security

Вкладка Security управляет административной безопасностью и внешним доступом.

### Что обычно настраивается здесь

- пароль администратора;
- TOTP;
- API keys;
- MCP access;
- webhook URL, secret и events.

### TOTP

TOTP стоит включать сразу после базовой настройки панели.

Рекомендуемый порядок:

1. Подготовьте приложение-аутентификатор.
2. Включите TOTP в панели.
3. Проверьте вход с кодом до завершения сеанса.
4. Сохраните резервные данные в безопасном месте.

### API keys

API keys нужны для внешней автоматизации и должны выдаваться по принципу минимально необходимых прав.

Рекомендации:

- создавайте отдельный ключ под каждую интеграцию;
- задавайте только нужные scopes;
- если доступ идёт из фиксированной инфраструктуры, ограничивайте IP;
- планируйте ротацию ключей и отзыв неиспользуемых.

### Webhooks

Webhooks полезны для реакции на события панели, но требуют аккуратной настройки.

Перед включением проверьте:

- доступность внешнего endpoint;
- корректность shared secret;
- минимально необходимый набор events;
- поведение при недоступности внешнего обработчика.

Если webhook настроен слишком широко, можно перегрузить внешнюю систему лишними событиями.

## Backup

Вкладка Backup отвечает за создание и хранение резервных копий.

### Что поддерживается

- локальные backups;
- отправка в S3-совместимое хранилище;
- ручной запуск backup;
- просмотр списка доступных backup-файлов;
- восстановление из локального или S3-источника.

### Рекомендованный режим

- включить автоматическое создание backups;
- хранить несколько последних копий локально;
- для production дублировать их в S3;
- отдельно проверять, что restore действительно работает, а не только backup создаётся.

### Важное ограничение

Restore заменяет текущие данные панели. Это не операция просмотра или теста, а полноценная замена базы.

Перед restore:

1. Убедитесь, что у вас есть актуальная резервная копия текущего состояния.
2. Поймите, какие данные будут потеряны после отката.
3. Запланируйте короткое окно обслуживания.

## Maintenance

Maintenance - вкладка с обслуживающими операциями повышенного риска.

### Что здесь обычно делают

- очищают кэш;
- сбрасывают трафик пользователей;
- очищают накопленную статистику;
- выполняют другие сервисные операции, влияющие на глобальное состояние панели.

### Почему это опасно

Эти действия затрагивают не один объект, а всю систему. Их удобно запускать, но последствия часто шире, чем кажется из названия кнопки.

### Правила безопасной работы

- сначала создайте backup;
- убедитесь, что понимаете масштаб операции;
- выполняйте сбросы в низконагруженное время;
- после завершения перепроверьте dashboard, stats и поведение подписок.

## Как подходить к изменениям в Settings

Используйте простой порядок:

1. Понять, изменение локальное или глобальное.
2. Проверить, затронет ли оно пользователей, узлы или интеграции.
3. Подготовить rollback-план.
4. Изменить только один логический блок за раз.
5. Сразу проверить фактическое поведение панели.

## Частые ошибки

- менять несколько критичных настроек сразу, а потом искать причину сбоя;
- включать webhook или MCP без чёткой схемы доступа;
- выполнять restore без предварительного backup текущего состояния;
- менять SSH pool и затем массово запускать node operations без теста на одном узле;
- рассматривать Subscription как косметическую вкладку, хотя она влияет на поведение клиентов.
