# Гайд по интерфейсу панели

Этот документ описывает повседневную работу администратора в веб-панели C3 CELERITY.

Для общего обзора структуры документации начните с [panel-overview.ru.md](./panel-overview.ru.md).

## Основные разделы панели

Панель делится на несколько рабочих зон:

- Dashboard - сводка по узлам, пользователям, трафику и активности.
- Users - управление пользователями, сроками действия, группами, трафиком и ссылками подписки.
- Groups - серверные группы и параметры подписочных пакетов.
- Nodes - управление Hysteria 2 и Xray VLESS узлами.
- Network Map - визуальная схема узлов и cascade links.
- Stats и System - наблюдение за системой, логами и состоянием панели.
- Settings - глобальные настройки, безопасность, backup и maintenance.
- Wizard - мастер первичной настройки.

## Вход и безопасность

### Первичный вход

При первом запуске панель предлагает создать администратора и завершить базовую настройку. После этого вход выполняется через страницу логина панели.

Что важно:

- доступ администратора защищён сессионной авторизацией;
- для чувствительных действий могут использоваться дополнительные проверки безопасности;
- после включения TOTP для входа понадобится одноразовый код.

### Рекомендуемый порядок после первого входа

1. Сменить пароль администратора на уникальный.
2. Включить TOTP.
3. Проверить базовые настройки панели в Settings.
4. Подготовить первую группу серверов.
5. Добавить узлы и только после этого создавать пользователей.

## Wizard

Wizard нужен для быстрого старта и помогает пройти типовой сценарий развертывания.

Он полезен, если вы:

- поднимаете панель впервые;
- хотите быстро развернуть стартовый узел;
- хотите сразу получить рабочий набор: узел, группу и администратора/пользователя.

Обычно мастер включает:

- выбор сценария развертывания;
- выбор протоколов;
- ввод параметров узла и SSH-доступа;
- показ прогресса выполнения шагов;
- выдачу итоговых реквизитов и стартовой конфигурации.

Если вы уже понимаете структуру своих узлов, можно обходиться без Wizard и настраивать всё вручную через Nodes, Groups и Settings.

## Dashboard

Dashboard используется как точка ежедневного контроля.

Обычно здесь смотрят:

- общее количество пользователей и узлов;
- текущий статус узлов;
- суммарный трафик;
- число online-подключений;
- последние синхронизации и служебные показатели.

Dashboard подходит для быстрой оценки состояния, но не заменяет детализацию из Users, Nodes, Stats и System.

## Users

Раздел Users отвечает за жизненный цикл подписчиков.

### Что можно делать

- создавать и удалять пользователей;
- включать и отключать доступ;
- назначать username и userId;
- ограничивать трафик;
- задавать срок действия;
- привязывать пользователя к одной или нескольким группам;
- копировать subscription link;
- открывать детальную карточку пользователя.

### Когда использовать группы

Группы полезны, когда один и тот же набор узлов и правил нужно выдавать многим пользователям. Вместо ручного назначения узлов каждому пользователю вы управляете пакетом через Groups.

### На что смотреть в списке пользователей

- статус пользователя: активен, отключён, просрочен;
- привязанные группы;
- текущий расход трафика;
- наличие лимита или безлимитного режима.

### Типовой сценарий

1. Создайте группу серверов.
2. Создайте пользователя.
3. Назначьте группу.
4. Проверьте срок действия, лимиты и параметры подписки.
5. Скопируйте пользователю subscription link.

### Риски и типовые ошибки

- пользователь без группы может получить не тот набор узлов, который вы ожидаете;
- отключённый или просроченный пользователь не пройдёт аутентификацию на узле;
- слишком жёсткие лимиты устройств и трафика часто выглядят для пользователя как нестабильная работа подписки.

## Groups

Groups нужны для логического объединения узлов и формирования подписочного пакета.

Через группы вы управляете:

- тем, какие узлы попадут в подписку;
- названием пакета, которое увидит клиент;
- цветом группы в интерфейсе;
- лимитом устройств на уровне группы, если он используется.

Группа - это не просто визуальный тег. В рабочей конфигурации она определяет, какие серверы и правила получает пользователь.

### Когда создавать отдельные группы

- для разных тарифов;
- для разных стран или регионов;
- для разных протоколов;
- для тестовых и production-пакетов;
- для выделенных enterprise или internal наборов.

## Nodes

Nodes - центральный раздел для управления инфраструктурой.

### Что поддерживается

- Hysteria 2 узлы;
- Xray VLESS узлы;
- смешанная инфраструктура, где оба типа управляются из одной панели.

### Базовые операции

- создание нового узла;
- редактирование существующего узла;
- клонирование узла или добавление paired protocol;
- включение и отключение узла;
- удаление узла;
- изменение порядка и приоритета;
- назначение групп;
- проверка статуса и числа online users.

### Что есть в карточке узла

- имя, IP, домен, флаг и порты;
- тип узла и служебная информация;
- статус online/offline/error;
- связанные группы;
- терминал и перезапуск;
- переход к полному редактированию.

### Auto setup и SSH

Панель умеет настраивать удалённые узлы по SSH. Это удобно для типового старта, но требует аккуратности:

- заранее проверьте SSH-доступ и права пользователя;
- убедитесь, что на хосте нет конфликтующих сервисов на тех же портах;
- не запускайте setup на production-узле без окна на проверку результата.

### Config preview

Перед применением конфигурации можно посмотреть, что именно панель собирается сгенерировать. Это полезно:

- перед rollout на новый узел;
- при отладке Xray/Hysteria-опций;
- при работе с ACL, routing и cascade.

### Terminal и Broadcast Terminal

Панель поддерживает два режима SSH-работы:

- Terminal - доступ к одному узлу;
- Broadcast Terminal - отправка одной команды на несколько узлов сразу.

Используйте их для диагностики, просмотра логов и единичных изменений. Не используйте broadcast для опасных команд без отдельной проверки целевых хостов.

## Network Map

Network Map показывает не только список узлов, но и связи между ними. Это особенно важно для cascade-сценариев.

Через карту удобно:

- видеть роли узлов;
- отслеживать связи portal, bridge и relay;
- быстро замечать broken или unhealthy links;
- оценивать общую топологию до и после развёртывания.

Подробные сценарии работы с каскадами описаны в [panel-advanced.ru.md](./panel-advanced.ru.md).

## Stats и System

Эти разделы нужны для контроля состояния панели и инфраструктуры.

### Что смотреть в Stats

- историю трафика;
- пользовательскую активность;
- накопленные snapshots;
- динамику нагрузки.

### Что смотреть в System

- системные показатели панели;
- служебные логи;
- ошибки синхронизации;
- состояние кэша и фоновых операций.

Если проблема затрагивает конкретный узел, сначала проверьте Nodes и terminal. Если проблема системная, переходите в System и Settings.

## Типовой рабочий порядок администратора

1. Проверить Dashboard и System.
2. Посмотреть проблемные узлы в Nodes.
3. Проверить затронутых пользователей в Users.
4. Если нужно, открыть terminal или broadcast terminal.
5. После изменений перепроверить Stats и доступность подписки.
